# 문서 여러 건 한 번에 내보내기

단일 문서 내보내기(Markdown 파일 / PDF 인쇄)는 v0.7.184에서 끝났다. **여러 건을 한 번에** 뽑는 기능은 범위가 달라 여기로 분리한다 — 사용자 요청으로 TODO 보류 (2026-09-21).

## 지금 되는 것

공유 팝오버(`ShareButton`)의 "파일로 내보내기" — 열려 있는 **문서 한 건**에 대해:

- `GET /api/vaults/{name}/pages/{slug}/export.md` → 원본 `.md` 저장 (frontmatter 포함, `?frontmatter=false`면 본문만)
- 렌더된 본문을 격리 iframe + A4 인쇄 스타일시트로 옮겨 `window.print()` → 사용자가 "PDF로 저장" 선택

구현: `dashboard/src/lib/pageExport.ts`, `raven/api/server.py::export_page_markdown`, 데스크톱 저장은 `save_download_file` 커맨드.

## 무엇을 더 정해야 하나

1. **선택 방법** — 사이드바 트리 다중선택 / 검색 결과 전체 / 태그·type 필터 / vault 통째. 어느 진입점에 붙일지가 첫 결정이다.
2. **묶는 형식** — 여러 `.md`를 zip으로? 한 권의 PDF로 합쳐서? 둘 다?
   - zip: 브라우저에서 zip을 만들려면 라이브러리가 필요하다 (의존성 승인 §10). 서버에서 `zipfile`로 만들면 표준 라이브러리로 끝나고 스트리밍도 쉽다 — **서버 쪽이 유력**.
   - 합본 PDF: 인쇄 방식(의존성 0)을 유지하려면 문서들을 한 인쇄 문서에 이어 붙이고 `break-before: page`로 나누면 된다. `pageExport.buildPrintDocument`가 이미 단일 문서용으로 그 구조를 갖고 있어 확장 여지가 있다.
3. **wikilink 처리** — 번들 안의 문서끼리 건 링크를 상대 경로로 바꿀지, `[[slug]]` 원문을 유지할지. 원문 유지가 Obsidian 호환에는 유리하다.
4. **규모 한계** — 수백 페이지 vault를 한 번에 요청했을 때의 응답 크기/시간. 상한과 진행률 표시가 필요한지.
